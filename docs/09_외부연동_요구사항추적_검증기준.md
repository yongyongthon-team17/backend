# 외부 연동·요구사항 추적·검증 기준

기능 35개 대응 관계와 구현 후 검증할 수용 기준입니다. 실제 서버 테스트 결과를 뜻하지 않습니다.

## 6. 외부 데이터 연동과 프론트 처리 순서

### 6.1 외부 연동과 자체 API의 경계

| 구분 | 호출·처리 주체 | 데이터 흐름 | 자체 API 반영 |
|---|---|---|---|
| 시설 CSV | Python 전처리/적재 작업 | 시설 기본정보 → facility, 유형 → facility_type | A01/A02/A03/A04에서 DB 조회 |
| 운영시간 CSV | Python 파싱/검증 | 시설·공간·요일별 시간 → operating_hour | A02/A03/A04가 공통 판정 |
| 주변 정류소 API | 적재/갱신 작업 | 시설 좌표 주변 정류소 검증·집계 → bus_stop_count | A05/A04는 저장된 수 사용 |
| 카카오 지도 SDK | FE | 시설 coordinates로 지도·마커·미니맵 표시 | 지도용 자체 API를 중복 생성하지 않음 |
| 현재 위치 | FE 브라우저 권한 | 선택적으로 A02에 사용자 위경도 전달 | 거리만 계산, 필수 검색 조건 아님 |
| LLM 서비스 | BE | 캐시 미스 시 검증된 운영/교통 사실 전달 → 문장 검증·캐시 | A04에서만 외부 생성 책임 |

공공데이터 API의 정확한 URL·인증 파라미터·페이지 크기·호출 한도는 첨부 문서에 없다. 제공기관 문서와 실제 응답 확인 후 별도 연동 명세로 정한다. 주변정류소 API라는 표현만으로 특정 기관의 Endpoint를 확정하지 않는다.

CSV 전처리는 GENERAL/READING/DEFAULT를 구분하고 요일 0~6으로 변환한다. source가 휴관을 명시하지 않은 행을 false 기본값만으로 열린 것으로 적재하지 않는다. 공공시설 운영시간을 LLM으로 추정해 DB 사실값처럼 저장하지 않는다.

버스 정류장 집계 실패는 null로 남기고 0으로 저장하지 않는다. 자료가 행정구 경계 밖 정류장을 포함하는지, API의 거리 단위/좌표계/페이징/중복 규칙을 검증한다. 캐시를 무효화할 수 있도록 운영시간·정류장 수 변경 시설을 추적하는 정책이 필요하다.

서버용 공공데이터/LLM 비밀키는 FE 응답에 넣지 않는다. 카카오 Web SDK의 JavaScript 키는 브라우저용 키로 구분하고 공식 도메인 정책에 맞춰 설정한다. 지도 SDK의 역할은 시각화이며 우리 운영시간 판정을 대신하지 않는다.

참고: [카카오 지도 공식 가이드](https://apis.map.kakao.com/web/guide/). 실제 키 설정이나 공급자 호출 테스트를 수행한 것은 아니다.

### 6.2 화면 연동 순서

1. A01로 실제 유형 ID를 받아 검색 선택지를 구성한다. 오늘 요일은 한국 시간 기준으로 초기화한다. 시작/종료 기본값은 UI 합의가 필요하다.
2. ‘열린 시설 찾기’ 시 A02를 호출한다. 결과 제목의 N은 totalCount, 카드/마커 키는 facilityId다.
3. 카드에 실제 매칭한 공간·요일 운영시간을 표시한다. 원문 화면 흐름을 유지하면서 GENERAL/READING의 시간을 섞지 않는다. UI 디자인에 공간 표시 위치를 합의한다.
4. 목록/지도 전환은 같은 응답과 조건을 유지한다. 지도에 보이는 시설 수는 현재 뷰포트에 표시된 시설의 수이며 matchedSpaceCount를 쓰지 않는다.
5. 카드·마커 선택 시 A03를 호출한다. 상세 주간 표는 공간별로 구분한다. AI 카드에서 온 경우 FE가 해당 spaceType을 강조한다.
6. 교통 P1을 구현하면 A05를 추가 조회한다. 실패해도 시설 상세 전체를 지우지 않는다.
7. AI 영역에서는 동일한 검색 기본 조건을 A04에 전달한다. A02 결과가 0건이어도 AI는 개선 대상을 찾을 수 있다.
8. 캐시 재사용/생성 여부는 API가 처리한다. 화면은 생성 상태·교통 제한·참고 문구를 표시하고 실패한 AI 영역만 재시도할 수 있게 한다.

### 6.3 화면별 상태 처리

| 상황 | FE 동작 |
|---|---|
| ALWAYS_OPEN | 상시 이용 표시. 운영시간 행이 없다고 휴관 표시 금지 |
| RESERVATION + AVAILABLE | 운영시간 적합과 예약 필요를 함께 안내 |
| UNKNOWN | 운영정보 확인 필요, 이용 가능 배지 금지 |
| amenities=null | 편의시설 정보 미제공. ‘없음’으로 표시하지 않음 |
| bus_stop_count=null | 정류장 정보 확인 불가; 0곳 표시 금지 |
| imageUrl=null | FE 공통 대체 이미지. 유형 기본 경로가 있으면 BE 제공 URL 사용 |
| A02 0건 | 200 빈 결과 안내; unknownSpaceCount가 있으면 미판정 상황 추가 |
| A04 후보 0건 | 개선 대상 없음; 미확인 공간이 있으면 단정 표현 피함 |
| A04 LLM 실패 | 현재 운영시간·불일치 계산 유지, AI 생성 실패 표시 |
| 캐시 저장 실패 | 이미 생성된 결과는 표시, 무한 재요청 금지 |
| 400/404/503 | 입력 오류/시설 없음/서비스 불가를 구분 |
| 이전 조건의 늦은 응답 | 새 결과를 덮어쓰지 않도록 요청 취소·순번·조건 비교 |

### 7.2 중복·누락 점검

- 카드·지도·지도 옆 목록은 A02 결과를 재사용한다. 별도 카드/마커 API가 없다.
- 시설 목록은 facilityId로 중복 제거한다. 공간 개수와 시설 개수를 분리했다.
- 상세·검색·AI는 공간별 동일 시간 판정 규칙을 사용한다.
- AI 불일치 계산은 현재 시간표, 생성 문장은 캐시에서 가져오는 역할을 분리했다.
- 기능명세서에 없는 공간 검색 필터·회원가입·예약 처리·관리자 적재 API는 추가하지 않았다.
- 편의시설 P0는 응답 필드를 유지하고 스키마 보완을 명시했다.
- 교통 등급·취약 시간·통합 개선안의 근거 부족을 구현 완료로 표시하지 않았다.
- 이미지와 주소/좌표 필수성은 현재 제공 모델에 맞췄다.

### 7.3 구현 수용 기준 — 아직 실행한 서버 테스트가 아님

| 번호 | 사례 | 기대 결과 |
|---|---|---|
| T01 | GENERAL 09~18 / READING 09~22, 희망 19~21 | A02 시설 1개·READING만 매칭; A04 GENERAL 후보 |
| T02 | 두 공간 모두 시간에 맞음 | A02 시설 1개·availableSpaces 2개, matchedSpaceCount=2 |
| T03 | 서로 다른 공간의 시간이 부분적으로만 요청을 덮음 | 합쳐서 전체 이용 가능으로 오판하지 않음 |
| T04 | 폐관과 희망 종료가 같음 | 전 구간 운영이면 AVAILABLE |
| T05 | 휴관 true | CLOSED·UNAVAILABLE, 요청 전체 미운영 |
| T06 | 시간 행 누락/null | UNKNOWN; is_closed=false 기본값만으로 OPEN 금지 |
| T07 | ALWAYS_OPEN + 운영시간 행 없음 | DEFAULT 가상 공간, 정상 매칭·AI 연장 후보 제외 |
| T08 | RESERVATION + 시간 적합 | AVAILABLE + requiresReservation=true, 예약 필요 표시 |
| T09 | 요일 변환 | DB/API 0=월, 6=일; 주말 오프셋 오류 없음 |
| T10 | 사용자 위치 미허용/좌표 한쪽만 전달 | 전자는 검색 정상·거리 null, 후자는 400 |
| T11 | 검색 결과 없음 | 200·items=[]·totalCount=0 |
| T12 | 없는 시설 ID | 404 FACILITY_NOT_FOUND |
| T13 | 주소/좌표 결측 원천 | 적재 검증에서 처리, 가짜 0 좌표를 정상 응답에 넣지 않음 |
| T14 | AI 동일 시설/요일/시간, 다른 spaceType | 서로 다른 캐시 행 조회 |
| T15 | 같은 유효 캐시 키 | HIT·기존 ID/생성일, LLM 재호출 없음 |
| T16 | 운영시간·정류장 수 변경 | 기존 캐시 무효화/근거 버전 검사 후 재생성 |
| T17 | 동시 동일 생성 | UNIQUE 중복 500 금지, 저장된 행으로 수렴; 중복 LLM 호출 제어 검토 |
| T18 | options가 손상된 JSON/객체/숫자 배열 | string[] 검증 실패, 유효 HIT로 반환하지 않음 |
| T19 | LLM 실패 / 캐시 저장만 실패 | 전자는 UNAVAILABLE, 후자는 NOT_STORED·생성 결과 유지 |
| T20 | 정류장 null vs 0 | NO_DATA/null과 AVAILABLE/0 구분 |
| T21 | 교통 자료는 없는데 기존 summary가 있음 | 현재 유효성 확인 없이 COMPLETE 재사용 금지 |
| T22 | 편의시설 컬럼 미추가 | amenities=null은 정보 없음. P0 태그 완료로 체크하지 않음 |
| T23 | 복수 운영 구간/주차별 휴관 원천 | 단순 합쳐서 시간 전체 운영으로 오판하지 않음 |
| T24 | 좌표·유형 join·목록/지도 전환 | 동일 facilityId와 결과 조건 유지 |
| T25 | 현재 요청보다 이전 응답이 늦게 도착 | 새 조건 결과 덮어쓰기 방지 |
