# 데이터테이블 v2 수정중

[이미지 — 노션 원본 페이지에서 확인 (ERD로 추정)]

시설 : 도서관, 체육시설, 평생학습관, 문화센터, 주민자치센터, 공용주차장, 보건소

→위 시설중 공공데이터에서 주차장(위치정보x),

보건 소, 문화센터, 평생학습관, 주민자치센터(정보 미흡)

특히 관공서 정보(주민센터)는 제가 따로 찾아봤는데 2019년 정보라 확인이 필요할 것 같습니다.

또 도서관 운영시간에 관련된 정보에서 일요일 운영시간이 표기되어있지 않은 곳이 있는데 이것도 어떻게 할지 상의가 필요할 것 같습니다.

이런 문제가 있어서 몇군데는 수동으로 입력을 해야할 것 같습니다. 다행히 개수는 몇 개 안되는거 같아요.

이 부분은 민수님이 올려주신대로 가면 될 것 같습니다.

ip정보나 그런건 db가 아니라 서버메모리에 넣는걸로 생각해봤습니다.

### 1. 테이블 개요

| 테이블 | 설명 | 쓰이는 기능 | 데이터 성격 |
|---|---|---|---|
| facility_type | 시설 유형 | 유형 필터 칩, 카드 기본 이미지 | 코드값 (직접 입력) |
| facility | 공공시설 기본 정보 | 키워드 검색, 지역 선택, 시설 카드, 지도 마커, 거리 표시, 상세 패널 | 공공데이터 적재 + 일부 직접 입력 |
| facility_amenity | 편의시설 태그 (NEW) | 상세 패널 편의시설 태그 (F23) | 공공데이터 매칭 |
| facility_space | 시설 공간 (NEW) | 공간 목록, 이용 가능 배지 문구, AI 분석 단위 | 적재 시 생성 |
| operating_hour | 공간·요일·구간별 운영시간 | 열린 시설 찾기, 이용 가능 배지, 요일별 운영시간표 | 공공데이터 적재 |
| ai_analysis | AI 분석 캐시 (범용) | 접근성 분석, 접근 취약지역, 운영 개선안 카드, 지역 핵심 인사이트 | 서비스 실행 중 LLM으로 생성 (유일한 쓰기 테이블) |

관계: facility_type 1 : N facility · facility 1 : N facility_amenity · facility 1 : N facility_space · facility_space 1 : N operating_hour · facility 1 : N ai_analysis (시설 단위 결과) · facility_space 1 : N ai_analysis (공간 단위 결과)

operating_hour는 facility가 아니라 facility_space를 (facility_id, space_type) 복합 FK로 참조합니다. 존재하지 않는 공간의 운영시간은 DB에 들어갈 수 없습니다. ai_analysis는 시설·공간 단위 행에서만 facility_id·space_type을 채우고(NULL 허용), 이때 존재하지 않는 시설·공간의 결과는 들어갈 수 없습니다.

### 2. facility_type (시설 유형)

| 컬럼 | 타입 | 제약 | 설명 |
|---|---|---|---|
| type_id | SMALLINT | PK, IDENTITY (자동 증가) | 유형 ID (코드에서 하드코딩하지 않고 name으로 조회) |
| name | VARCHAR(30) | NOT NULL, UNIQUE | 도서관 / 생활체육시설 / 주민자치센터 / 보건소 / 평생학습관 / 문화센터 |

| default_image | VARCHAR(255) |  | 카드 기본 이미지 경로 (시설 사진 데이터가 없어 유형별 이미지 사용) |

### 6. operating_hour (공간·요일·구간별 운영시간) — R05 · R06

| 컬럼 | 타입 | 제약 | 설명 |
|---|---|---|---|
| facility_id | BIGINT | PK, FK → facility_space | 시설 ID |
| space_type | VARCHAR(20) | PK, FK → facility_space | 공간 구분 |
| day_of_week | SMALLINT | PK, CHECK (0~6) | 0=월 … 6=일 (JPA에서 TINYINT는 Byte로 매핑돼 SMALLINT로 통일) |
| interval_seq | SMALLINT | PK, DEFAULT 1, CHECK (≥ 1) | 같은 요일 안의 구간 번호 (점심 휴게, 하루 두 번 운영) — R05 |
| day_state | VARCHAR(10) | NOT NULL, CHECK | OPEN / CLOSED / UNKNOWN — R06 |
| open_min | SMALLINT | CHECK (0~1439) | 개장 시각. 자정부터의 분 (09:00 = 540) |
| close_min | SMALLINT | CHECK (1~1440) | 마감 시각. 자정 마감 24:00 = 1440 |

제약/인덱스: PK (facility_id, space_type, day_of_week, interval_seq) · FK (facility_id, space_type) → facility_space ON DELETE CASCADE · INDEX (day_of_week, day_state, open_min, close_min)

CHECK 규칙:

- OPEN이면 open_min·close_min 필수이고 open_min < close_min
- CLOSED / UNKNOWN이면 시간 NULL, interval_seq = 1
- 시각을 TIME이 아닌 분(SMALLINT)으로 저장하는 이유: Java LocalTime·H2가 24:00을 표현하지 못하고, 실제 데이터에 '09:00 ~ 24:00'이 있음. API에서는 "HH:mm"으로 변환

**day_state 코드**

| 값 | 의미 | 적재 규칙 |
|---|---|---|
| OPEN | 해당 구간 운영 | 시간 쌍이 유효할 때 |
| CLOSED | 매주 고정 휴관 | 원천 00:00–00:00, '매주 월요일' 등 |
| UNKNOWN | 정보 없음 | 빈칸·파싱 실패. 행이 아예 없어도 UNKNOWN으로 처리하고 휴관으로 보지 않음 |

'둘째·넷째 월요일' 같은 격주 휴관은 closed_day_note에만 기록하고 월요일 전체를 CLOSED로 바꾸지 않습니다 (R07).

### 7. ai_analysis (AI 분석 캐시, 범용) — R08 · R09 · R10

LLM이 만든 분석 결과를 종류(analysis_type)별로 payload(JSON)에 통째로 저장하는 캐시 테이블입니다. 종류마다 컬럼을 만들지 않아 LLM 출력 형태가 바뀌어도 DB를 고치지 않아도 됩니다.

| 컬럼 | 타입 | 제약 | 설명 |
|---|---|---|---|
| analysis_id | BIGINT | PK, IDENTITY (자동 증가) | 분석 ID |
| scope_key | VARCHAR(40) | NOT NULL, UQ 묶음 | 대상 문자열. FAC:12(시설) / DIST:수지구(구) / ALL(전체). NOT NULL이라 UNIQUE가 동작함 (PostgreSQL UNIQUE도 기본적으로 NULL끼리 같다고 보지 않음) |
| analysis_type | VARCHAR(30) | NOT NULL, CHECK, UQ 묶음 | 결과 종류 (아래 코드표) |
| params_key | VARCHAR(40) | NOT NULL, DEFAULT '', UQ 묶음 | 종류별 추가 키. IMPROVEMENT는 S:GENERAL\|D:1\|T:1140-1260 (공간\|요일\|희망 분 구간), 나머지는 빈 문자열 |
| facility_id | BIGINT | NULL 허용, FK → facility (ON DELETE CASCADE) | 시설·공간 단위 행에서만 채움 |
| space_type | VARCHAR(20) | NULL 허용, FK (facility_id, space_type) → facility_space (ON DELETE CASCADE) | 공간 단위 행에서만 채움 (IMPROVEMENT) |
| payload | JSONB | NOT NULL, CHECK (jsonb_typeof(payload) = 'object') | 종류별 결과 객체. 앱에서 종류별 payload 클래스로 검증 후 저장 — R09 |
| source_hash | CHAR(64) | NOT NULL | LLM에 넘긴 입력 근거(운영시간 행, bus_stop_count, 편의시설 등)의 SHA-256 — R08 |
| prompt_version | VARCHAR(20) | NOT NULL | 프롬프트 버전 (예: v1). 분석 종류별로 따로 관리해 한 종류만 올리면 그 종류의 캐시만 무효화 — R08 |
| model_name | VARCHAR(50) |  | 생성 모델명 |
| created_at | TIMESTAMP | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 최초 생성 시각 |
| updated_at | TIMESTAMP | NOT NULL, DEFAULT CURRENT_TIMESTAMP | 재생성 시각 (JPA @UpdateTimestamp로 앱에서 갱신. PostgreSQL에는 ON UPDATE가 없음) |

제약: UNIQUE (scope_key, analysis_type, params_key) · FK facility_id → facility ON DELETE CASCADE · FK (facility_id, space_type) → facility_space ON DELETE CASCADE

**analysis_type 코드**

| 값 | 화면 | 대상 | payload 내용 |
|---|---|---|---|
| ACCESSIBILITY | 상세 패널 '시설 접근성 분석 결과' | 시설 | 점수, 등급, 요약, 지표 목록 |
| VULNERABLE_AREA | '접근 취약지역' | 시설 | 지역명, 거리, 이유, 추천 |
| IMPROVEMENT | 'AI 운영 개선안' 카드 | 시설(공간) + 요일·시간 | 카드 배열(뱃지, 제목, 설명, 효과, 상세), 제안 종료 시각(분) |
| REGION_INSIGHT | '이번 주 핵심 인사이트' | 구 또는 전체 | 핵심 문장, 지표 |

캐시 HIT 조건: 키가 일치하고 source_hash·prompt_version이 현재 값과 같을 때. 다르면 다시 생성해서 UPDATE합니다. 생성이나 검증에 실패한 결과는 저장하지 않습니다.

LLM 입력 원칙: 백엔드가 계산할 수 있는 값(저녁 운영 시설 비율, 정류장 수, 주차 면수 등)은 입력으로 넘깁니다. 접근성 점수·효과 수치처럼 근거 데이터가 없는 지표도 결과에 포함될 수 있어, 프론트에서 'AI 분석 결과이며 참고용' 경고 문구를 항상 표시합니다.

※ '운영시간 불일치 분석'은 저장하지 않고 operating_hour와 희망 시간을 비교해 그때그때 계산

### 8. 화면 정책

| 화면 | 정책 |
|---|---|
| 열린 시설 찾기 · 결과 수 | 선택한 시간 칩 구간 안에서 공간 중 하나라도 OPEN이면 포함 (구간과 겹치는 OPEN 구간이 있으면 됨: operating_hour 테이블의 open_min < 구간 끝 그리고 close_min > 구간 시작). ALWAYS_OPEN은 항상 포함. 카드에는 실제 운영시간을 그대로 표시 |
| 요일 선택 | 요일은 단일 선택(복수 선택 없음), 기본값은 오늘. 선택한 요일이 operating_hour 테이블의 day_of_week 한 값으로 조회에 들어감 |
| 시간 칩 | 지금 = 현재 시각 · 오전 = 06:00–12:00 (360–720분) · 오후 = 12:00–18:00 (720–1080) · 저녁 = 18:00–24:00 (1080–1440). 저녁을 다음날 06시까지 잡지 않는 이유: 운영시간을 하루 0~1440분 안에 저장해 자정을 넘는 구간은 표현하지 않음 |
| 이용 가능 배지 | 모든 공간이 열려 있으면 '이용 가능', 일부만이면 '열람실만 이용 가능'처럼 space_name 표시. UNKNOWN이면 '운영시간 확인 필요'. access_type에 따라 '상시 이용' / '예약 필요' 태그 |
| 시설 카드 | 대표 운영시간은 GENERAL(없으면 DEFAULT), 열람실은 보조 한 줄 |
| 상세 패널 운영시간표 | 공간별 행(또는 탭), 구간이 여러 개면 '09:00–12:00, 13:00–18:00' + closed_day_note. ALWAYS_OPEN은 '별도 운영시간 없이 상시 이용 가능' |
| 상세 패널 편의시설 | facility_amenity 태그 + detail, READING 공간이 있으면 '열람실' 태그 |
| 정보 기준일 | source_updated_at |
| AI 분석 (상세 패널) | ai_analysis의 종류별 결과를 그대로 표시. 개선안은 공간 단위로 제안하고 ALWAYS_OPEN은 대상 제외 |

### 9. ETL 규칙 (DB 제약으로 걸 수 없는 것)

| 규칙 | 관련 |
|---|---|
| 재적재는 (source_type, source_key)로 UPSERT. DELETE 후 다시 INSERT하지 않음 | R17 |
| GENERAL·READING 공간은 도서관 유형에만 생성. 모든 시설에 facility_space 1행 이상 | R10, R18 |
| 평일/주말 시간은 요일 7행으로 풀어서 저장. 같은 요일의 OPEN 구간끼리 겹치지 않음 | R05 |
| 원천 00:00–00:00은 CLOSED, 빈칸·파싱 실패는 UNKNOWN | R06 |
| 격주·월별 휴관은 closed_day_note에만 기록 | R07 |
| 좌표가 없으면 도로명주소로 지오코딩. 실패하거나 용인시 범위 밖이면 적재하지 않고 격리 목록에 기록 (범위 밖 행이 섞이면 INSERT 전체가 CHECK로 실패) | R16 |
| 전화번호는 trim 후 적재. district는 원천 '행정구명'이 아니라 주소에서 판별 | R18 |

| 시각은 "HH:mm" ↔ 분 변환, 요일은 DayOfWeek.getValue() - 1 (0=월), hibernate.jdbc.time_zone=Asia/Seoul, payload는 @JdbcTypeCode(SqlTypes.JSON), analysis_type은 Java enum + @Enumerated(EnumType.STRING) | R18 |
| ai_analysis의 scope_key와 facility_id가 일치해야 함 (FAC:12 ↔ facility_id 12, DIST·ALL이면 NULL). payload는 종류별 클래스로 검증 후 저장하고 검증 실패 결과는 저장하지 않음 | R09 |

| operating_hour가 바뀌면 source_hash가 달라져 다음 조회 때 AI 캐시가 자동 재생성됨 | R08 |

| 부설주차장 PARKING 태그는 공백을 넼 시설명이 같을 때만 붙임 (일치하는 시설이 없으면 0행) | R01 |
