# DB 매핑·보완 및 논의 사항

기능 요구사항을 유지하기 위한 데이터 테이블 매핑과 보완 사항입니다.

## 2. 데이터 테이블 ↔︎ API 매핑

### 2.1 제공 모델에서 확인된 사실

- `facility_type` 1:N `facility`, `facility` 1:N `operating_hour`, `facility` 1:N `ai_suggestion`.
- 공공데이터 CSV를 Python으로 전처리해 DB에 넣는 방향이다. 이는 제안된 적재 방식이며 실행된 사실은 아니다.
- 서비스 요청 중 쓰기 대상은 ai_suggestion 캐시다. ETL은 당연히 시설·시간·유형 데이터를 적재/갱신할 수 있다.
- operating_hour PK는 `(facility_id, space_type, day_of_week)`이므로 같은 공간·요일에 운영 구간을 두 개 저장할 수 없다.
- ai_suggestion UNIQUE는 `(facility_id, space_type, day_of_week, req_start, req_end)`다.
- ERD는 일부 코드를 enum처럼 표시하고 본문은 VARCHAR+CHECK로 표기한다. 의미상 코드 집합은 같지만 실제 DDL/DBMS는 별도 확정이 필요하다.

### 2.2 facility_type

| DB 컬럼 | API 필드 / 처리 | 설명 |
|---|---|---|
| type_id SMALLINT PK | typeId: integer | 예시 ID를 도서관=1 등으로 하드코딩하지 않음 |
| name VARCHAR(30) NOT NULL UNIQUE | typeName / A01 name: string | 도서관·생활체육시설 등 DB에 있는 유형 |
| default_image VARCHAR(255) | defaultImageUrl / imageUrl: string / null | 상대 경로면 공개 이미지 기준 URL을 붙이는 방식 제안; 기준 URL 미정 |

### 2.3 facility

| DB 컬럼 | API 필드 / 처리 | 설명 |
|---|---|---|
| facility_id BIGINT PK | facilityId: string | 10진수 문자열로 전달 제안 |
| type_id SMALLINT FK | typeId: integer | facility_type join으로 typeName·imageUrl 제공 |
| district VARCHAR(10) | district: string(enum) | 수지구 / 기흥구 / 처인구 |
| access_type VARCHAR(20) | accessType: string(enum) | OPEN_HOURS / RESERVATION / ALWAYS_OPEN |
| name VARCHAR(100) | name: string | 시설명 포함 검색 |
| address VARCHAR(255) NOT NULL | address: string | 주소 포함 검색 |
| latitude DECIMAL(9,6) NOT NULL | coordinates.latitude: number | WGS84인지 실제 원천 좌표계 검증 필요 |
| longitude DECIMAL(9,6) NOT NULL | coordinates.longitude: number | API에서는 JSON 숫자로 변환 제안 |
| phone VARCHAR(20) | phone: string / null | 상세 연락처 |
| closed_day_note VARCHAR(255) | closedDayNote: string / null | 표시용 원문. 날짜별 휴관 판정 테이블이 아님 |
| bus_stop_count INT nullable | transport.stopCount: integer / null | 원문 반경 500m; null=미확인, 0=확인 결과 0곳 |
| data_updated_at DATE | dataUpdatedAt: string(date) / null | 원문상 정보 갱신일. 원천 기준일인지 적재일인지 합의 필요 |

성공 응답에서 시설 주소·좌표는 non-null이다. 적재 전에 누락·오류를 검증하고 처리 방식을 정해야 한다. 좌표를 0으로 채워 정상 시설처럼 공개하지 않는다. 데이터 누락 시설을 유지해야 한다면 DB NOT NULL과 API 계약을 함께 바꿔야 한다.

### 2.4 operating_hour

| DB 컬럼 | API 필드 / 처리 | 설명 |
|---|---|---|
| facility_id PK/FK | facilityId에 종속 | 시설별 공간 목록을 구성 |
| space_type PK | spaceType: string(enum) | GENERAL / READING / DEFAULT |
| day_of_week TINYINT PK | dayOfWeek: integer | 0=월요일 … 6=일요일 |
| open_time TIME nullable | openTime: string(time) / null | 해당 공간·요일의 단일 개장 시각 |
| close_time TIME nullable | closeTime: string(time) / null | 해당 공간·요일의 단일 마감 시각 |
| is_closed BOOLEAN | DaySchedule.state로 변환 | true→CLOSED; false와 유효 시간 쌍→OPEN; 결측·비정상→UNKNOWN |

is_closed는 매주 고정 휴관만 의미한다. ‘매월 둘째·넷째 월요일’ 같은 설명을 보고 모든 월요일을 is_closed=true로 바꾸지 않는다. 행 없음·시간 null을 자동 휴관으로 취급하지 않는다.

### 2.5 ai_suggestion

| DB 컬럼 | API 필드 / 처리 | 설명 |
|---|---|---|
| suggestion_id BIGINT PK | suggestionId: string / null | 재사용/저장된 캐시 행 ID; 저장 실패면 null |
| facility_id FK | item.facility.facilityId | 현재 존재하는 시설인지 검증 |
| space_type | item.spaceType | 분석 대상 공간. 캐시 키에 포함 |
| day_of_week | criteria.dayOfWeek | 캐시 키에 포함 |
| req_start / req_end | criteria.startTime / endTime | 캐시 키에 포함; 유효 시간 구간 검증 필요 |
| suggested_close TIME nullable | proposedClosingTime: string / null | 현재 운영시간을 수정하지 않는 제안값 |
| options TEXT | alternatives: string[] | JSON 문자열 파싱 후 배열로 전송. 이중 JSON 문자열로 반환하지 않음 |
| summary TEXT | integratedSuggestion.text: string / null | 캐시된 통합 개선 문장 |
| created_at TIMESTAMP | cache.createdAt: string(date-time) / null | DB/애플리케이션 시간대 설정을 합의해 RFC 3339로 변환 |

운영시간 불일치 구간은 매번 현재 operating_hour와 요청 조건으로 계산한다. 캐시에는 생성 문장을 저장한다. district/keyword/typeId는 후보 선택에만 쓰고 동일 시설·공간·요일·시간에 대한 내용이 같다는 전제에서 캐시 키에서 제외한다. 지역 전체 종합 문장을 생성하려면 이 키만으로는 부족하다.

### 2.6 현재 스키마에 없는 요구사항·필드

| 항목 | 현재 상태 | v0.2 처리 |
|---|---|---|
| 편의시설 태그(F23) | 저장 컬럼/관계 없음 | 상세 amenities=null로 명시. 태그 기능 충족에는 데이터·스키마 보완 필요 |
| 실제 시설 사진 | facility에 사진 필드 없음 | 유형별 기본 이미지 사용 |
| 공식 홈페이지 URL | 컬럼 없음; 원문은 확인 권고 문구 | 실제 URL 필드를 임의로 만들지 않음; 상세는 전화번호 제공 |
| 정류장 목록·좌표 | bus_stop_count만 저장 | A05는 개수만 조회; 목록/정류장 지도 기능은 추가하지 않음 |
| 교통 등급 기준 | 테이블 및 산식 없음 | grade=null. 기준 합의 후 계산 필드로 제공 가능 |
| 배차간격·막차·취약 시간 | 운행 데이터/저장 구조 없음 | weakTimeAnalysis=NOT_SUPPORTED, P1 확장 필요 |
| 공휴일·임시/주차별 휴관 | closed_day_note는 표시용 | 정규 주간시간 기준임을 표시; 정확한 날짜 판정 미지원 |
| 수집 시각·출처·교통 자료 기준일 | 별도 컬럼 없음 | 과거 v0.1 collectedAt/sources 등은 정상 응답 계약에서 제거 |
| 예약 가능 여부·잔여석 | access_type만 있음 | 예약 필요만 표시. 예약 가능·확정으로 표시하지 않음 |
| AI 상태·근거 버전·만료 | 현재 캐시 컬럼 없음 | 캐시 상태는 요청 처리 결과로 계산. 무효화 정책 추가 논의 |

## 5. 테이블 보완 및 추가 논의 사항

### 5.1 기능을 유지하기 위해 필요한 정합성 조치

아래는 **수정 권고**이며 원본 테이블이 변경되었다는 뜻은 아니다. 핵심 요구사항을 테이블 때문에 축소하지 않고 미충족 항목을 드러냈다.

| 번호 | 요구/문제 | 현재 모델의 한계 | 권고 / 확정할 사항 |
|---|---|---|---|
| R01 | F23 편의시설 태그 P0 | facility에 태그 정보 없음 | 데이터 출처 확보 후 facility_amenity 관계 또는 amenities JSON 필드 등 저장 방식 추가. 임시 null은 미완료 표기 |
| R02 | F08/F10/F14/F22/F25 공간별 시간 정합성 | 한 시설에 GENERAL·READING이 있어 시설 단일시간으로 표현 불가 | API에 실제 매칭 공간·공간별 주간시간 포함. UI 공간 필터는 추가하지 않음. 어떤 공간 하나 매칭이면 포함할지 합의 |
| R03 | 예약제 시설의 이용 가능 배지 | RESERVATION은 예약 상태를 담지 않음 | 운영시간과 예약을 구분해 ‘예약 필요’ 표시. 실제 예약 가능 확인은 원문 범위 외 |
| R04 | 상시 이용 시설의 시간 판정 | ALWAYS_OPEN은 operating_hour 없음 | DEFAULT 가상 공간·00:00–24:00 판정. 원천의 상시 개방 여부 검증 |
| R05 | 하루 복수 운영 구간·휴게시간 | PK로 공간/요일당 1행만 가능 | 원천에 복수 구간이 있으면 interval_seq를 PK에 추가하거나 별도 구간 테이블. 확장 전 임의 합치기 금지 |
| R06 | UNKNOWN과 휴관 구분 | is_closed 기본 false, 시간 컬럼 nullable | is_closed=false만으로 OPEN 판정 금지. OPEN=양쪽 시간 유효, CLOSED=true, 나머지 UNKNOWN. DB 제약과 적재 검증 보강 |
| R07 | 날짜별 예외 휴관 | closed_day_note 표시용뿐 | 요일 기준 검색과 한계를 유지. 실제 방문일 보장이 필요할 때 날짜 입력/예외 테이블을 합의해 추가 |
| R08 | AI 캐시의 최신성 | UNIQUE 키에 운영시간/교통/프롬프트 버전 없음 | ETL 변경 시설의 캐시 무효화, 프롬프트/모델 변경 시 재생성 정책. 또는 sourceVersion/expiresAt 등 추가 |
| R09 | AI options·상태 검증 | TEXT JSON 형식 강제 없음; 생성 상태/근거 메타 없음 | 앱에서 string[] 검증 후 저장. status/근거 버전 저장 여부 논의. 손상·부분 실패를 유효 HIT로 쓰지 않음 |
| R10 | AI 키와 운영공간 관계 | facility FK만으로 공간 존재까지 보장하지 않음 | 서비스에서 시설-공간 조합 검증. 공간 제거 시 캐시 정리. 필요하면 시설공간 테이블 도입 |
| R11 | F24 교통 등급 P1 | bus_stop_count 외 기준 없음 | 등급 산식 합의·ruleVersion 관리. 임의 양호 판정 금지 |
| R12 | F30 취약 시간 P1 | 노선·방향·요일별 운행/배차 자료 없음 | 확장 데이터를 확보해 산식 정의. 정류장 개수로 배차간격 추측 금지 |
| R13 | F31 통합 개선안 P0와 교통 P1 충돌 | 교통 미적재 시 통합 근거 부족 | 교통 최소 근거를 확보하거나 팀이 P0 범위 변경을 명시 결정. 이 문서가 임의로 제외하지 않음 |
| R14 | 500m 정류장 수 집계 정확성 | INT 결과만 남아 검증 근거/시각 부족 | 정류장 ID 중복제거·500m 경계·인접 시 정류장 포함·호출 실패 null 규칙. 계산일/출처 보완 검토 |
| R15 | 정보 갱신일 표시 | data_updated_at 의미 모호 | 원천 데이터 기준일로 쓸지 적재일로 쓸지 확정. 둘 다 필요하면 별도 컬럼 |
| R16 | 좌표·주소 NOT NULL | 공공 원천 결측 가능 | ETL 검증/보완·격리 후 공개하거나 nullable 정책과 API 동시 수정. (0,0) 가짜 값 금지 |
| R17 | 시설 동일성 및 안정 ID | UNIQUE(name,address)는 표기 변경/공유주소 충돌 가능 | 원천 sourceId·sourceType 매핑 검토. 재적재 시 AUTO_INCREMENT ID 바뀌지 않게 유지 |
| R18 | day/time/access 코드 제약 | 일부 CHECK 구체식·DBMS 미정 | 0~6, 코드 집합, start<end, count>=0, 공간/유형 적합성 등 실제 DDL 검증 |

특히 R01은 기능명세서에 이미 있는 P0 필드라 ‘없으니 삭제’할 대상이 아니다. R05는 다중 시간 구간이라는 새 UI를 요구하는 것이 아니라 실제 원천 시간을 잘못 합쳐 기존 시간 검색 기능을 오판하지 않기 위한 조건부 보완이다. 복수 구간이 없는 데이터만 확보한다면 지금 테이블을 유지할 수 있다.

### 5.2 현재 테이블 구조를 유지할 수 있는 부분

- facility_type, facility, operating_hour, ai_suggestion의 4개 중심 테이블과 1:N 관계는 그대로 활용할 수 있다.
- 검색마다 사용자 위치·검색 조건을 DB에 저장할 필요는 없다.
- 거리, 이용 가능 여부, 불일치 구간, 응답 개수는 계산값이다. 모두 컬럼으로 추가할 필요는 없다.
- API의 공간별 배열도 운영시간 행을 묶어서 만들 수 있다. 별도 공간 테이블은 공간 무결성·확장 요구에 따라 선택한다.
- 정류장 배지를 위해 매번 외부 API를 호출할 필요는 없다. 적재된 개수로 시작하고 집계/등급 근거를 정한다.
- AI 제안 캐시의 기존 UNIQUE는 ‘시설·공간·요일·희망 구간별 제안’ 단위와 맞는다. 다만 변경 무효화가 필요하다.

### 5.3 아직 팀 합의가 필요한 정책

| 구분 | 미정 사항 | 본 초안의 제안 |
|---|---|---|
| 인증 | 공개/로그인/익명 세션, CORS·권한 | 임의 방식 확정 없음 |
| 요일·유형 | 요일 단일/복수, 유형 복수 여부 | 요일 단일, 유형 OR 복수 제안 |
| 시설 포함 | 어느 공간 하나 충족 vs 모든 공간 충족 | 하나 이상 충족하되 실제 공간명을 표시 |
| 예약 시설 | 검색 포함 여부·배지 문구 | 포함+예약 필요 안내, 예약 가능 보장은 안 함 |
| 시간 | 분 단위, 24:00·익일, 원천 초 단위 | 일내 HH:mm, 종료 24:00 제안. DBMS 매핑 확인 필요 |
| 데이터 유형 | 도서관/작은도서관/학습관/체육시설 실제 범위 | 시설 유형은 원천 확보 후 결정, 예시를 지원 확정으로 취급하지 않음 |
| 거리 | FE/BE 계산, 직선/경로 | BE 직선거리 제안 |
| 지도 | 현재 지도 범위 내 목록 vs 검색 결과 전체 | 같은 A02 결과에서 FE 뷰포트 필터 제안 |
| AI 대상 | 시설별 공간 카드를 모두 표시할지 묶을지 | 공간별 분석 결과, FE에서 시설별 그룹 가능 |
| AI 생성 | 모델·timeout·동기/비동기·개수·캐시 TTL·비용 | 캐시 우선 동기 200 계약 제안, 수치 미정 |
