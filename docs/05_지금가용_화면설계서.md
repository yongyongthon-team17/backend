# 용용톤- 지금가용 화면설계서

## 1. 화면 목록

| ID | 화면명 | 주요 내용 |
|---|---|---|
| 00 | 공통 UI | 상단 메뉴, 로고, 이용 안내, 오류·로딩 표시 |
| 01 | 메인 검색 | 지역, 요일, 시간, 키워드 검색 |
| 02 | 시설 검색 결과 | 검색된 시설 목록, 필터, 지도 보기 전환 |
| 03 | 지도 보기 | 시설 위치 표시, 마커와 목록 연동 |
| 04 | 시설 상세 | 시설 정보, 요일별 운영시간, 이용 가능 여부 |
| 05 | AI 개선 제안 | 운영시간 불일치 분석, 개선안 제시 |

02와 03은 목록/지도 보기로 전환하는 방식이고, 04는 시설을 클릭했을 때 오른쪽에 뜨는 상세 패널로 구성한다.

## 2. 화면별 기능

### 00. 공통 UI

- 상단 메뉴: 시설 찾기 / 지도 보기 / AI 개선 제안 / 이용 안내
- 메뉴를 누르면 해당 화면으로 이동하고, 현재 보고 있는 메뉴는 구분해서 표시
- 로고를 누르면 메인 검색 화면으로 이동
- 데이터 불러오는 중에는 로딩 표시, 오류가 나면 안내 문구와 재시도 버튼 표시
- 실제 운영 여부는 시설에 한 번 더 확인하도록 하단에 안내 문구 표시
- 이용 안내는 우선순위가 낮아 MVP 구현 후 추가 검토

### 01. 메인 검색

- 키워드: 시설명이나 주소 입력
- 지역: 용인시 전체 / 수지구 / 기흥구 / 처인구 중 선택 (기본값: 용인시 전체)
- 요일: 월~일 중 하나 선택 (기본값: 오늘)
- 시간: 시작 시간과 종료 시간 선택
- 종료 시간이 시작 시간보다 빠르거나 같으면 검색하지 않고 오류 안내
- ‘열린 시설 찾기’를 누르면 조건에 맞는 시설을 검색해 02로 이동

### 02. 시설 검색 결과

- 검색한 요일·시간과 결과 개수 표시
- 시설 카드에 시설명, 유형, 주소, 운영시간, 이미지 표시
- 선택한 시간에 운영하는 시설은 ‘이용 가능’ 배지 표시
- 시설 유형별 필터 제공 (도서관, 체육시설 등)
- 시설 카드를 누르면 04 상세 패널 열기
- ‘목록 / 지도’ 탭으로 02와 03 전환. 검색 조건과 시설 유형 필터는 그대로 유지 (피그마 화면에 반영됨)
- 결과가 없으면 ‘이 시간에 열린 시설이 없어요’ 문구와 조건 변경 안내 표시
- 시설 카드에는 ‘시설 상세 보기’ 버튼, 시설 유형·구·거리·운영시간·주소 등이 표시됨 (피그마 기준)
- 거리 표시는 피그마에 있으나 실제 위치 기반 계산 여부는 확인 필요 (위치 권한 필요)
- 북마크는 추가 기능으로 검토. 피그마에 아이콘이 있으나 저장한 시설을 모아 볼 화면은 아직 확인되지 않음
- 북마크를 구현한다면 검색 결과에 ‘저장한 시설’ 탭을 추가하는 방식 제안 (로그인 없이 브라우저에 저장하는 방식 검토)

### 03. 지도 보기

- 지도 탭을 선택하면 검색된 시설의 위치를 마커로 표시 (지도 API 연동 방식은 개발 시 확인)
- 마커를 누르면 해당 시설이 선택되고 옆 목록에서도 강조
- 반대로 목록에서 시설을 선택하면 지도에서도 위치 표시
- 피그마에서는 지도 아래 시설 목록이 표시됨. 시설명, 유형, 운영시간 등 간단한 정보 제공
- 시설을 선택해 04 상세 패널 열기
- 목록 보기로 돌아가도 검색 조건은 유지

### 04. 시설 상세

- 시설 카드에서 ‘시설 상세 보기’를 누르면 오른쪽 상세 패널 열기. 기존 화면은 어둡게 표시
- 상단에 시설 사진, 시설 유형·지역, 시설명과 닫기(X) 버튼 표시
- 검색한 요일·시간에 이용 가능한지 안내하고 실제 운영시간도 함께 표시
- 시설 정보: 주소, 전화번호, 편의시설 태그, 정보 갱신일 표시 (피그마 기준)
- 교통 접근성: 접근성 배지, 시설 위치 미니 지도, 인근 정류장과 버스 노선 정보 표시 (피그마에 디자인됨, 실제 구현은 데이터 확보 후 검토)
- 요일별 운영시간: 월~일 운영시간과 휴관일 표시, 검색한 요일은 강조
- 닫기 버튼이나 패널 바깥 영역을 누르면 이전 화면으로 복귀
- 하단에 운영시간은 참고용이며 방문 전 최신 정보를 확인하라는 안내 표시
- 운영시간 기준으로 판단하는 것이므로 실제 예약이나 이용 가능 여부와는 다를 수 있음

### 05. AI 개선 제안

- 사용자가 원하는 시간과 실제 시설 운영시간을 비교
- 운영하지 않는 시간대가 있다면 얼마나 차이 나는지 표시
- 피그마 기준 ‘AI 운영시간 인사이트’ 영역과 운영시간 개선안 카드를 표시
- 운영시간 불일치, 실행 가능한 선택지, 교통 접근성, 접근 취약 시간, 통합 개선안 항목으로 구성
- 예: 화·목 주 2회 운영시간 시범 연장
- 제안 이유와 현재 운영시간도 함께 보여주기
- 교통 접근성 분석, 접근이 어려운 시간대 분석은 데이터 확보 상황에 따라 추가
- 개선 전후 효과 시각화는 MVP 이후 검토
- AI 제안은 실제 운영 정책이 아닌 참고용이라는 안내 문구 표시

## 3. 사용자 흐름

### ① 시설 검색

1. 메인에서 지역, 요일, 시간 선택
2. ‘열린 시설 찾기’ 클릭
3. 검색 결과 목록 확인
4. 필요하면 시설 유형 필터 적용
5. 원하는 시설 클릭
6. 상세 패널에서 운영시간 및 시설 정보 확인

01 → 02 → 04

### ② 지도에서 시설 찾기

1. 검색 결과에서 지도 보기 클릭
2. 지도에 표시된 시설 마커 확인
3. 마커 또는 옆 목록에서 시설 선택
4. 시설 상세정보 확인
5. 패널을 닫으면 지도 화면으로 돌아감

02 → 03 → 04 → 03

### ③ AI 개선 제안 확인

1. 상단 메뉴에서 AI 개선 제안 화면 이동
2. 분석할 시설과 희망 시간 확인
3. 실제 운영시간과 희망 시간 비교
4. 운영시간이 부족한 구간과 AI 개선안 확인

상단 메뉴 → 05

시설 상세 화면에서 AI 제안으로 바로 이동하는 버튼을 넣을지는 팀에서 추가로 정해야 한다.

### ④ 검색 결과가 없을 때

1. 조건에 맞는 시설이 없으면 안내 문구 표시
2. 사용자가 요일이나 시간을 변경
3. 다시 검색해 결과 확인

01 → 02(결과 없음) → 조건 변경 → 02

## 4. 화면 이동 정리

```
01 메인 검색
  ↓
02 시설 검색 결과 ↔ 03 지도 보기
  ↓                    ↓
  └──── 04 시설 상세 ────┘
         (닫으면 이전 화면)

상단 메뉴 → 05 AI 개선 제안
```

## 5. 추가 회의할 부분

### ① 목록/지도 전환 방식 (피그마 반영됨)

- 피그마에 ‘목록 / 지도’ 탭이 이미 있어서 전환 방식은 별도 논의 없이 이 구조를 기준으로 진행해도 될 듯.
- 검색 조건과 시설 유형 필터를 유지하면 좋을 듯 → 목록과 지도를 오갈 때 다시 검색할 필요가 없음.

### ② 시설 상세에서 AI 개선 제안으로 이동

- 상세 패널에 ‘AI 개선안 보기’ 버튼을 넣으면 좋을 듯 → 사용자가 시설 운영시간을 확인하다가 바로 개선안을 볼 수 있음. AI 기능을 찾으려고 상단 메뉴로 다시 이동할 필요도 없음.
- 버튼을 누르면 해당 시설과 검색한 요일·시간이 AI 화면에 전달되는 방식 제안.

### ③ AI 분석 대상 선택 방식

- 기능명세서에는 상단 메뉴에서 AI 개선 제안 화면(05)으로 이동하는 기능은 있지만, 어떤 시설을 분석 대상으로 선택하는지는 구체적으로 정해져 있지 않음.
- 시설 상세에서 선택한 시설을 그대로 분석 대상으로 넘기는 게 좋을 듯 → 시설을 다시 검색하거나 선택하는 과정이 줄어듦.
- 상단 메뉴에서 AI 화면에 바로 들어왔을 때는 분석할 시설을 선택하는 기능이 필요할지 논의.

### ③-1. AI 운영시간 개선안 분석 기준 확인

- 피그마의 AI 개선안은 사용자가 원하는 이용 시간과 시설의 실제 운영시간을 비교하고
부족한 시간만큼 야간 운영 연장 등을 제안하는 형태임.
- 예: 희망 시간 19:00~22:00 / 실제 운영시간 09:00~21:00
→ 부족한 21:00~22:00에 대한 연장 운영 제안.
- 이용 희망 시간과 운영시간이 일부라도 맞지 않는 시설을 어떤 기준으로 분석할지 정하면 좋을 듯
→ AI 제안에 사용할 시설과 시간 차이를 일관되게 계산할 수 있음.
- 기능명세서에는 ‘선택한 시간에 열린 시설 검색’이 적혀 있으므로 운영시간이 일부만 겹치는 시설을 검색 결과에 표시하는지도 확인 필요.
- 별도의 ‘닫힌 시설 보기’ 기능을 추가하는 것으로 확정하지 않고
기존 검색과 AI 분석의 연결 방식부터 팀에서 확인하는 방향.

### ④ 교통 접근성 분석

- 이번 MVP에서는 후순위로 두는 게 좋을 듯 → 버스정류장·노선 등 추가 데이터가 필요하므로 운영시간 검색과 AI 개선안부터 완성하는 게 중요함.
- 피그마 AI 화면에는 ‘반경 500m 내 버스 정류장’ 등 교통 접근성 분석 카드가 이미 있음. 다만 디자인에 있다고 MVP 구현이 확정된 건 아님.
- 데이터가 확보되면 시설 상세나 AI 화면에 간단한 정보부터 반영하는 방향 제안.

### ⑤ 지역별·시간대별 접근성 분석

- 핵심 기능을 완성한 뒤 추가하는 게 좋을 듯 → 이전 회의에서도 5순위로 정했고, 지역 전체의 접근성이나 취약지역을 분석하려면 별도 기준과 데이터 처리가 필요함.
- 우선 개별 시설의 운영시간 불일치 분석부터 구현.

### ⑥ 북마크 및 저장한 시설 보기

- 피그마 시설 카드에 북마크 아이콘은 있지만, 저장한 시설을 모아 보는 화면은 확인되지 않음.
- 북마크를 넣는다면 ‘저장한 시설’ 탭도 같이 만들면 좋을 듯
→ 자주 가는 시설을 매번 검색하지 않고 다시 확인할 수 있음.
- 로그인 없이 브라우저에 저장하는 방식이면 비교적 간단하지만
다른 기기와 저장 목록이 공유되지 않는 점은 안내 필요.
- 기능명세서에서는 MVP 외/P2이므로 핵심 기능을 완성한 후 추가할지 결정.

### MVP 이후 검토할 기능

- 북마크 및 저장한 시설 보기: 편의 기능으로 추가 후보.
- 개선 효과 시각화: 개선 전후 비교는 추후 추가 기능으로 검토.

우선 시설 검색 → 목록/지도 확인 → 시설 상세 → AI 운영시간 개선 제안 흐름을 완성하는 방향으로 진행하면 좋을 것 같다.
